## 安装过程

1. 先备份旧 1.9.0 完整驱动、固件、辅助内核集合和 NVRAM。正常关闭 VM，确认 libvirt 为 `shut off`，再使用 XFS reflink 保存系统 qcow2、可写 EFI raw、交付盘、UEFI NVRAM 和未激活的 VM XML。备份盘 `qemu-img check` 无错误；备份保留在私有目录。
2. 启动旧系统，传输官方包、候选包和探针，核对 SHA-256。官方 `CHECK=1` 预检通过，测试内核集合包含四个扩展。
3. 运行官方安装器。因机器加载了 WhateverGreen，按安装器提示在实际 EFI 配置的 `boot-args` 增加 `gfxrst=4`，保存原文件，用 OpenCore 1.0.5 的 `ocvalidate` 验证，回读并卸载 EFI。
4. 第一次重启后，确认 NVRM、NVRMFB、NVRMAGDC、NVAccel 均为 2.3.6，Metal 3 和 VNC 正常。官方原版对照探针返回 `encoder_create=-12908`，没有恢复 H.264 NVENC 注册，符合预期。
5. 对指定候选运行只读检查。通过 GPU、已加载内核版本和完整官方 bundle 摘要校验后，另存官方用户态 bundle，原子应用覆盖包，验证签名和两个二进制摘要，第二次重启。
6. 保留初始探针的原始失败报告，诊断并修复下述探针兼容问题。使用 v2 正式探针先做 30 帧短测，再暂停光梭后台进行 3600 帧持续验收；结束后恢复光梭。
7. 现有光梭 Mac 主机的生产编码路径自测也通过。恢复后确认光梭进程及 UDP 47990、macOS VNC 5900 和 Metal 3 正常。

## 本次发现并修复的问题

**PCI 树遍历。** 初始应用工具只读 `ioreg` 数组顶层，漏掉 PCI 桥后第二层的真实 3060，因而拒绝应用。修复为遍历子树，按 `IORegistryEntryID` 去重；重复 ID 的属性冲突仍拒绝。单张 NVIDIA 显示设备、精确 `2504`、内核版本与摘要限制全部保留。新增测试覆盖嵌套、重复、第二张卡和音频设备。

**软件解码器属性。** 初始 v1 探针已经创建精确 NVENC 硬件编码器并产出第一帧，但 Apple 软件解码器对硬件状态查询返回 `kVTPropertyNotSupportedErr`（`-12900`），探针在解码前提前退出。独立诊断在解码前后均得到该状态，且 30 帧像素正确。

正式探针升级 schema/probe v2，记录明确的 `EnableHardwareAcceleratedVideoDecoder=false` 创建参数、成功创建状态和真实查询状态。属性不支持时 `decoder_hardware_used` 为 `null`；其他错误或矛盾字段仍不通过。完整依据及两条允许的证据路径见[硬件验收](hardware-acceptance.md#软件解码证据与报告版本)。这是验收工具修正；编码端仍强制使用 NVENC，禁止软件编码回退。

## 回滚与后续更新

本次没有触发回滚。旧 1.9.0 的完整离线 VM 备份与官方 2.3.6 用户态 bundle 备份均保留。

同版本覆盖包回滚使用应用工具的 `--restore`，之后重启。若需恢复完整旧 1.9.0，应先正常关闭 VM、确认关机，保存当前失败现场，再从完整离线备份恢复系统盘、EFI 和 UEFI NVRAM；启动后核对旧编码库摘要并重测远控。官方 `uninstall.sh` 不承担完整旧版本恢复。

下次升级继续按“固定上游及摘要 → 审阅新 profile → Actions 构建 → 离线备份 → 官方安装并重启 → 覆盖检查和应用并重启 → 短测 → 持续验收 → 光梭实际路径”执行。未知二进制不能复用旧偏移；本次成功不改变新构建的 `hardware_validation: not-run` 默认值。
